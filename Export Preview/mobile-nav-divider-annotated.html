Layers between 04 and 05

04A
Generated pseudo-element box content: "" and height: 13px; this is the CSS-only box that carries the separator treatment.
04B
Transparent pass-through surface background: transparent; the box does not paint an opaque paper band.
04C
Negative placement offset bottom: -13px; positions the generated box immediately below the header boundary.
04D
Shadow paint / visual separator box-shadow: 0 6px 12px rgba(...); the offset and blur create the visible soft strip.
04E
Header paper surface and box edge .site-header supplies background: var(--paper); its border-box edge is the protected stacking boundary.
05A
Buffer starts inside the header The buffer begins above the separator, not below the generated shadow box.
05B
10px mobile bottom padding padding: 16px 16px 10px; the final value creates the clearance below the nav links.
05C
Protected lower header boundary The content disappears when it crosses the opaque header edge, before it can visually sit inside the nav pane.

What happens during the scroll

The transition is a stacking and geometry behavior, not a JavaScript animation.

  1. 1. Before the boundary .intro-label is fully visible below the sticky header's opaque edge.
  2. 2. Crossing the boundary The label's box moves upward into the sticky header area and becomes partially covered.
  3. 3. Covered state The header background and stacking order cover the label; the shadow strip remains visible below the header.

In the live page, the transition is controlled by position: sticky, top: 0, the mobile padding-bottom: 10px, the ::after shadow, and z-index: 10 on .site-header.

What this is

A geometry explanation of where the header's opaque surface, generated shadow layer, and mobile padding sit during scroll.

What this is not

It is not an extra opaque 33px guard, not a separate DOM separator element, and not a JavaScript-driven hiding animation.
